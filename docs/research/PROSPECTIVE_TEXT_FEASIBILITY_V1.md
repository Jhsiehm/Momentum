# Prospective text feasibility: implementation draft v1

November 8, 2026. **Read-only repository assessment and proposed next implementation, not an experiment registration, collection run, forecast, protocol amendment or source certification.** No new source requests, outcome access, model fitting, prediction or scoring occurred in preparing this draft. The [historical comparison](MATCHED_TEXT_COMPARISON_V1.md) remains blocked. The [synthetic preflight](../operations/runs/20261108-matched-text-synthetic-preflight.md) established software behavior, not historical eligibility or predictive efficacy.

## Decision

Build a small **source-only capture ledger** before attempting a prospective text forecasting service. It should preserve exact introduced-text bytes and the time they were actually acquired, with a deterministic discovery ledger, independent timestamp evidence, and replayable source-to-structure mappings. It must have no model-fitting, forecasting or outcome-scoring entry point. A bounded, preregistered collection pilot can close this engineering gap while historical evidence work continues.

This solves a future observation problem. It does not retroactively authenticate the eight unresolved historical objects, supply missing reviewed historical training examples, or create a trained text model. If historical training remains unavailable, newly observed cohorts must first mature into a separate development/training population; a later untouched cohort is then needed for independent text-model evaluation. Collecting text today cannot remove that waiting time.

## Smallest implementation deliverable

Create a separately versioned collector and an independent verifier. Before live requests, freeze a finite manifest naming the exact cases or the outcome-blind inventory rule, allowed official routes, maximum bill records (no more than 100 per bounded cycle), request/byte/time/retry budgets, handling of redirects and interruptions, required response types, and stopping dispositions. The source-only pilot must identify its sampling frame and cannot claim census completeness. A source route failure permits only the registered retry of that identity; it does not justify choosing an easier replacement.

Every request should produce an immutable receipt, including failed, empty, truncated or interrupted attempts. The receipt contract should contain:

- Study/version and case identity; request URL without credentials; allowed/final host and redirect disposition; request start and completion times generated by the collector; HTTP status and selected non-secret headers; exact received byte count and SHA-256; complete/incomplete disposition.
- Official package/version/bill identity checks; declared publication and legislative effective dates kept separately from actual observation time; parser and source-format versions; source URL and provenance rationale. A mismatch is quarantined, not corrected by guessing a bill identity.
- Exact raw-byte path in ignored `data/`, atomic exclusive file creation, verification of any preexisting content-addressed bytes, canonical receipt hash and predecessor receipt hash. Keep operational retry/cursor state separate from this append-only ledger.
- Immutable inventory/discovery response and discovery-receipt binding; first discovery time; scheduled checkpoint where relevant; retained exclusions and failures. Preserve the exact response before parsing, including discovery JSON.
- External timestamp receipt and its verification result when available. If unavailable, label the receipt **local observation only**; source capture may be useful operationally but must not satisfy an independent prospective issuance gate.
- Optional structural sidecar/view hashes generated by the frozen structural implementation, with no learned vocabulary or model output. Sidecar validation failure must leave original bytes and the failure receipt intact.

Clock rollback, duplicate/concurrent writes, interrupted acquisition, wrong bill/version, HTTP error bodies, unexpected content, truncated bytes, digest mismatch, invalid timestamp evidence, date-only ambiguity and parsing failures need adversarial fixtures. The verifier should independently rehash raw bytes, validate the chain and identity bindings, and reject later bytes substituted under earlier receipts. Test original code under normal and optimized Python; explicit checks must not rely on assertions for production validation.

The exit result is a complete per-case capture/readiness ledger, with denominators for attempted requests/cases, complete captures, identity-valid text, structural-valid text, external timestamp coverage and unresolved cases. It is **not** a count of historically eligible sources, semantic extraction accuracy, forecasts or prediction accuracy. No live collection is represented as having happened in this draft.

## Availability rules that must not be weakened

A publication date identifies what a source says about an event; it does not prove when our exact bytes were available. Set the new capture's local availability bound conservatively to completed acquisition. A later externally timestamped digest establishes evidence of possession by that later timestamp; it does not move availability backward to a printed introduction date. Independent attestation must precede the relevant prediction cutoff if it is to establish pre-cutoff possession under that route. The source's own response headers cannot replace it.

Introduced text acquired today can be used at a future checkpoint only if its identity/version and availability are established by that checkpoint. A current snapshot cannot serve as an earlier missed checkpoint. Keep all versions; do not silently replace introduced language with amended or final text. A capture of an old bill today is forward evidence of today's observation, not a new prospective prediction of its already observed outcome.

Separate operational risk-set checking from protected evaluation labels. A future issuance service needs authorized pre-issuance checks for already-resolved bills, but neither the collector nor model developers should gain a general protected-outcome feed through that exception. Actual public-outcome awareness must be logged; technical separation cannot make public facts unknowable.

## Later forecasting design: requirements before registration

The existing [paper protocol](PAPER_PROTOCOL_V1.md) is a structured fixed-artifact study. Its planned Congresses 120/121, four procedures, exact trained artifacts, practical-effect hypotheses and access rules cannot automatically be repurposed for the new text comparison. The [matched introduced-text specification](MATCHED_TEXT_COMPARISON_V1.md) is an exposed historical development comparison and is also not a prospective launch authorization. Any prospective text study needs its own separately reviewed, sealed protocol and finite fit budget before affected outcomes are accessed.

For compatibility, retain the existing scientific target unless a separately justified study changes it: own-bill public-law enactment strictly after the day-180 checkpoint and strictly before Congress end; H.R./S. only; no resolutions, incorporation into another bill or private-law substitution. Introduction plus exactly 180 days defines the checkpoint, with existing date-only normalization and explicit boundary adjudication. Require checkpoint before Congress end and the bill still at risk at issuance. Negatives mature only after horizon closure and audited complete public-law coverage. Missing labels are unresolved, not zero.

A prospective text protocol would have to settle all of the following before issuance:

1. Outcome-blind census/discovery rule, finite collection cadence and coverage reconciliation; exact future periods and expiry/deadline; one paired prediction per eligible bill/checkpoint and explicit missed/late dispositions.
2. Eligible, reviewed, time-correct and family-separated core/calibration training populations; frozen text vocabulary/IDF, structured scales, solver, calibration and trained artifacts. The synthetic fixture does not supply these. Preserve the required human/source/family/outcome reviews and applicable class/positive-family adequacy rules; agents cannot certify the original human gates.
3. Anchor versus anchor-plus-text as the sole incremental feature question, plus correctly trained rate/stage reference losses. No conditional descriptor arm until its gate passes. Define the total model/calibration fits and runtime budget, rather than borrowing unused fits from an old protocol.
4. An independently reviewed issuance adapter that freezes publication-based features and all paired probabilities atomically at the checkpoint; model/source/code/registration hashes, actual cutoff/observation/issue times, predecessor hash and externally verified timestamp receipt. The paper's 60-second issuance tolerance is an existing contract, not a capability already provided by the live collector. No historical replay or late issuance fills a missed forecast.
5. A real custodian/access arrangement for labels, exposure logging, training/evaluation family intersections and later-discovered related-bill links. Operational completeness monitoring must not reveal interim model losses. Frozen forecasts remain immutable if a later link invalidates independent-inference eligibility.
6. Fixed outcome adjudication, complete census coverage, missing-outcome sensitivity and event floors. The current paper specifies at least 200 reviewed positive training families, 100 reviewed development positives when selection is proposed, and 100 evaluation positives per period/200 unique pooled. These are adequacy gates rather than a power calculation. Any distinct text protocol must explicitly resolve applicability before using a different population; collecting longer until a favorable score or event count appears is not allowed.

## Evaluation and the 60% aspiration

Register the success criterion before outcomes, with identical eligible cases for both model arms and reference baselines. Report calibrated and raw Brier loss (mean squared probability error), log loss, class-specific Brier, fixed-bin reliability/counts, expected events, coverage and missingness, and every period's sign. Use equal-period mean losses for the primary aggregate and compute skill as one minus their ratio; pooled bill-weighted loss is secondary. Zero reference loss makes the skill ratio undefined.

The existing paired global-family bootstrap design is a useful specification reference: 10,000 draws, seed 20261105, common family multiplicity across periods, explicit invalid empty-period draws, and no interval-based claim with fewer than 9,000 valid draws. A new text protocol must verify its implementation and declare its comparison family, interval multiplicity and missingness rules; it cannot reuse a confidence level while adding hypotheses. Few Congresses do not justify population-wide significance claims merely because there are many bills.

A claim of 60% relative Brier reduction against historical rate requires a prespecified contrast of equal-period mean `Brier_text − 0.40 × Brier_rate`, simultaneous inference appropriate to all declared primary claims, and the full source/family/issuance/custody gates. It does not mean 60 percentage points of accuracy. It is not a stopping rule or guaranteed result. The existing structured paper instead tests a 2% practical improvement against three comparators; leave that protocol unchanged. This draft produces neither contrast nor any predictive performance estimate.

## Calendar reality and stopping decision

Under the existing repository protocol, the whole-Congress 120/121 study must freeze before January 3, 2027 at 17:00 UTC. Congress 120's horizon ends January 3, 2029; Congress 121's ends January 3, 2031, both at 17:00 UTC under the repository's horizon function. The existing paper's protected outcomes are not unlocked until the latter horizon closes and adjudication finishes. These are protocol boundaries, not a promise that launch prerequisites will be ready or labels will be complete that day. Missing the launch boundary requires a new future design; no backdating.

A separately designed shorter pilot could measure collection reliability earlier, but not the same matured enactment target earlier. Switching to a shorter outcome would answer a different scientific question and require a separate protocol. Likewise, source collection alone does not produce an eligible trained text model before 2027. If newly captured 120 data must train that model, it cannot also be its untouched evaluation period, and development labels must mature before training; later evaluation and calibration needs then determine the actual schedule.

The immediate stop/go decision is therefore narrow: implement and adversarially verify the source-only collector, then register one bounded acquisition pilot if its route and evidence requirements can be met. Report a blocked external-attestation or coverage result honestly. Continue the eight-case historical source investigation independently because a successful historical training route could shorten model development substantially; do not acquire thousands of uncertified current renditions to manufacture progress. No automatic retraining, promotion or deployment is introduced here.
