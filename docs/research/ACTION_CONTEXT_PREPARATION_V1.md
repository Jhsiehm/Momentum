# Action-context offline preparation v1

This separately registered substantive successor follows the reviewed November 9 action-context proposal. It uniformly reprocesses the same 12,000 acquired identities (2,000 per Congress113–118), with no download, replacement, labels or fitting. The previous publication comparison remains blocked, zero fits. The source sample and prior label/class failure are already development-exposed. This is adaptive retrospective preparation, not an untouched test or historical-availability certification.

The new baseline is exactly [recorded action milestone / 3, Senate indicator]. Only sourceSystem numeric9 receives milestone meaning: HR5000/S14000 reporting=1; HR8000/S17000 origin passage=2;28000 presentation=3. Maximum strictly before introduction+180days; default0 denotes no selected milestone assertion. No publication completeness gate applies. Neither enactment, signing, latest action, opposite-chamber passage nor H30000 becomes a milestone.

Require calendar-valid introduction, cutoff strictly before Congress end, supported nonempty action container and at least one pre-cutoff action. Validate every top-level action date and source representation, including later history, and reject dates before introduction. Source categories are the frozen v2 categories; named Senate is never assigned a numeric code. Other action codes remain opaque and cannot create milestones. The action scalar must still be unambiguous. Later structural validity conditions eligibility, so selection is not purely pre-cutoff. Exclusions must be retained and their already-exposed public-law assertion association reported separately, without treating assertions as labels.

Three contexts call unchanged frozen helpers independently: v1 active cosponsors, v2 referral breadth and v2 recency. Recency retains its own stricter code-representation guard and may be missing while referral breadth remains observed. The subsequent challenger has8columns (2baseline+3training-median-imputed contexts+3missing indicators). All-missing training context stops fitting. The outcome resolver is directly imported unchanged from v2 and never invoked during preparation.

Before extraction, validate exact original registration dependencies, all12,000 unique IDs and ledger membership, six equal strata, mandatory raw/receipt/prior-feature files, successful receipt disposition, receipt hash against ledger, raw byte hash/size, and prior feature identity/hash. Freeze input hashes, source hashes and selected identities in an exclusively created registration. Original helper dependencies remain bound by original input registration; v2 and the new extractor/wrapper/tests/protocol are explicitly bound here. Check cutoff and related identities unchanged before saving each new feature. Each case remains in the ledger; exceptions are retained without replacement. Output changes records the old publication baseline and new action baseline for every successfully prepared case; their numerical values have different meanings.
